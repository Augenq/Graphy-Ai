# Backend: как устроен агент

Бэкенд выполняется в Rust; Python предоставляет тонкий запускатель и загрузку библиотеки. HTTP-протокол описан в [protocol.md](protocol.md), пользовательские сценарии — в [README бэкенда](../README.md).

## Слои

```text
frontend → HTTP /api/v1 и SSE
          → Rust backend_runtime: сервер, сервис, события и управление сессиями
          → runtime_agent / runtime_tools: цикл агента и инструменты
          → provider_runtime: HTTP/SSE провайдеров, модели, авторизация и web
          → state_runtime: сессии, курсы, вопросы, учебные события и хранилище
          → agent / context / providers / questions: чистые операции
```

Исходники находятся в `backend/rust/src/`. `graphy/__main__.py`, `graphy/native.py` и серверный адаптер передают управление Rust. Промпты и схемы остаются ресурсами данных. Python не реализует второй production runtime и не нужен исполняемому файлу `graphy-backend`. Для Python-запуска требуется Python 3.12+, сторонних runtime-зависимостей Python нет. Сборка из исходников требует Rust/Cargo 1.89+ и системного linker.

`graphy serve` передаёт аргументы серверу: порт, разрешённые Origin, рабочий каталог и опцию завершения при закрытии stdin. Сервер слушает loopback; в Docker `GRAPHY_SANDBOX=docker` разрешает сеть контейнера, при этом порт публикуется на loopback хоста. Готовность публикуется одной JSON-строкой в stdout; диагностика идёт в stderr. Токен, Origin и Host проверяются на границе API. `GET /api/v1/health` дополнительно возвращает `engine: "rust"`. Формат событий и маршруты остаются совместимыми с [протоколом](protocol.md).

## Состояние и учебный цикл

Rust управляет асинхронным циклом модели и инструментов, отменой, очередями и рассылкой событий. Вызовы инструментов могут читать файлы и выполнять команды в рабочем окружении. Учебные инструменты управляют планом, оценками и блоками вопросов; открытый блок приостанавливает цикл до ответа или отмены. Публичные проекции скрывают ключи ответов.

Журнал сессии хранится в JSONL; настройки, авторизация и каталог моделей — в `settings.json`, `auth.json` и `models.json` в `GRAPHY_DIR` (по умолчанию `~/.graphy`). Курсы, ответы и прогресс хранятся в каталоге `learning/courses`. Блокировка защищает сессию от одновременных писателей; целые события восстанавливаются при повреждённом хвосте. Прогресс является перестраиваемым кешем. Локальный формат данных сохраняет совместимость с прежним бэкендом.

Rust реализует транспорты провайдеров, потоковые ответы, каталог и discovery, Codex OAuth, управление внешним llama.cpp router, web-поиск и чтение. Возможности модели зависят от выбранного сервиса; см. [PROVIDERS.md](../PROVIDERS.md). Содержимое файлов и результаты инструментов используются как данные для модели.

## Библиотека и проверки

`graphy-core` собирается как Rust-библиотека и динамическая библиотека с версионированным JSON C ABI. `graphy_backend_main` запускает runtime, а `graphy_core_call` сохраняет интерфейс чистых операций; детали владения памятью и сборки — в [rust/README.md](../rust/README.md).

Из `backend/`:

```sh
python scripts/build_native.py
cargo test --locked --manifest-path rust/Cargo.toml
```

Rust unit- и HTTP-тесты проверяют нативную реализацию. `tests/reference_graphy` — тестовый оракул прежнего Python-поведения, отдельно от поставляемого runtime; Rust его не вызывает. Автоматические тесты не заменяют проверки реального провайдера и урока.

## Docker

`backend/Dockerfile` собирает библиотеку в Rust-этапе; запуск через `scripts/sandbox.cjs` использует Python-адаптер и собранную библиотеку. Хеш сборки учитывает вложенные Rust-файлы и JSON-ресурсы. Политика файловой системы сохраняется: код монтируется read-only, данные и рабочая папка доступны на запись, контейнер запускается с ограничениями и портом на loopback. Подробности монтирования и прав — в [README проекта](../../README.md).

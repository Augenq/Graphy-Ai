# Архитектура

Graphy состоит из четырёх частей. Всё, что исполняется на сервере, живёт в одном Docker-образе.

```text
Браузер / MAX WebView
   │  HTTPS
   ▼
Caddy (TLS)  ──►  scripts/web-server.mjs   статика сайта + прокси /api, /hub, /llm
                      │
                      ├─ режим одного пользователя:  прокси ──► агент (Rust) 127.0.0.1:8765
                      └─ режим MAX (MAX_BOT_TOKEN):  scripts/max-hub.mjs
                            ├─ вход по подписи initData / ссылке от бота, роли, классы
                            ├─ «Школа» (scripts/school.mjs): задания, тесты, результаты
                            ├─ /llm: прокси к провайдеру моделей, ключ остаётся здесь
                            ├─ бот MAX (long-poll): /start, ссылки входа, админ-команды
                            └─ по одному агенту на пользователя, под отдельным uid
```

## Компоненты

| Часть | Где | Что делает |
|---|---|---|
| Сайт | `frontend/` | React 19 + TypeScript + Vite, компоненты `@maxhub/max-ui`; чат, настройки, поиск, вкладка «Школа», мобильная версия |
| Веб-сервер и хаб | `scripts/*.mjs` | раздаёт сайт, проверяет вход, проксирует запросы к агенту, хранит роли, классы и задания (`hub.json`, `school.json`) |
| Агент | `backend/rust/` | HTTP API `/api/v1` и события SSE; цикл «модель ↔ инструменты»; провайдеры моделей; журнал занятий, память и прогресс |
| Python | `backend/graphy/`, образ | тонкий запускатель агента (загружает Rust-библиотеку) и интерпретатор для песочницы агента |
| Голос | `stt/` | сервис распознавания речи (faster-whisper); хаб принимает WAV и отдаёт текст |
| Поиск | `searxng/` | метапоиск для `web_search` |

## Агент

Один ход занятия: сообщение ученика → контекст (инструкции режима, состояние занятия, память) → модель → вызовы инструментов → ответ потоком событий.

Инструменты: `read`, `bash`, `web_search`, `web_read`, `load_skill`, `set_learning_plan`, `record_assessment`, `finish_lesson`, `ask_questions` (формы с вопросами), `show_widget`, `present_file` (файл для просмотра и отправки в класс), `spawn_researcher` (изолированный поиск в вебе). Промпты режимов лежат в `backend/graphy/prompts/`, схемы и ресурсы в `backend/graphy/resources/`.

Режимы: «Объяснение» (`explain`), «Квиз» (`quiz`: вопросы приходят только блоками `ask_questions`, ключи ответов скрыты, итог пишется в память), «Материалы» (`materials`: файлы документов). Ответы на вопросы записываются как свидетельства освоения; прогресс перестраивается из журнала.

## Данные

Всё хранится файлами, база данных не нужна.

| Путь в контейнере | Содержимое |
|---|---|
| `/data/settings.json`, `auth.json`, `models.json` | настройки агента, ключи провайдеров, каталог моделей |
| `/data/learning/` | журналы занятий (JSONL), память, прогресс, календарь |
| `/data/hub/` | `hub.json` (пользователи, роли, классы, список доступа), `school.json`, `secret` (ключ подписи сессий) |
| `/data/users/<id>/` | отдельный каталог данных агента каждого пользователя MAX |
| `/workspace/` | рабочие файлы агента, загрузки и файлы для просмотра |

## Безопасность

- Агент слушает только loopback; каждый запрос проверяется по `Host`, `Origin` и bearer-токену. Токен задаётся при старте и наружу не публикуется.
- Вход в MAX: подпись `initData` проверяется HMAC-SHA256 ключом бота, сравнение за постоянное время, срок до 24 ч, дата из будущего отклоняется. Ссылка от бота — подписанный токен без срока действия; доступ проверяется при каждом входе, отозвать его можно удалением пользователя из списка. Список доступа ведёт администратор бота.
- Ключ провайдера моделей не попадает в агентов: они ходят в `/llm` хаба с персональным токеном; запросы ограничены по размеру и числу в сутки.
- Публичный уровень сервиса Graphy (для локальных установок, `anon-<токен>`): три модели, потолок `max_tokens`, суточные лимиты по оценке стоимости на токен, IP и в целом; выключатель `GRAPHY_PUBLIC_LLM=off`.
- Каждый агент пользователя запускается под своим uid; хаб не следует симлинкам в каталогах агента при записи и смене владельца.
- Инструмент `web_read` не открывает локальные и частные адреса (loopback, RFC 1918, link-local, metadata) и редиректы на них.
- Контейнер: без Linux-capabilities кроме необходимых хабу, `no-new-privileges`, лимиты памяти и процессов; в режиме хаба корневая файловая система только для чтения, писать можно в `/tmp`, `/data`, `/workspace`.

Известные ограничения безопасности перечислены в [roadmap.md](roadmap.md).

## Развёртывание

Образ собирается из `Dockerfile` в три этапа: Rust-ядро (`rust:bookworm`), сайт (`node:22`), итоговый слой на `python:3.12-slim-bookworm` с Node, ядром, LaTeX, OCR и Python-библиотеками из `requirements.txt`. Ядро обязано собираться в Debian bookworm, иначе библиотека не загрузится из-за версии glibc: `scripts/docker-build.sh` делает это в контейнере.

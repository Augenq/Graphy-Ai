# Известные ограничения и план доработки

## Не проверено

- Работа внутри настоящего MAX WebView (проверялось в обычном браузере и по API с подписанными данными).
- Голосовой ввод на продакшене и нагрузка на сервер с несколькими одновременными агентами.
- Юзабилити на живых учителях и учениках: сценарии «Школы» пройдены автоматически, но не на реальных пользователях.

## План

**Приоритет 1**
1. Пройти руками в MAX: `/start`, вход, роль, чат, «Школа» (выдать тест, пройти, проверить).
2. Освободить место на сервере и настроить мониторинг диска и памяти.
3. Сменить пароль root на сервере, перейти на ключи SSH.

**Приоритет 2**
4. Назначение роли учителя только администратором (сейчас роль выбирается самостоятельно); ограничить показ ключей ответов.
5. Лимиты `/llm`: белый список моделей, потолок `max_tokens`, суточный бюджет с сохранением счётчиков.
6. Токен в строке запроса для SSE заменить на заголовок или одноразовый тикет; отзыв сессий.
7. Закрыть агенту чтение файла с ключами (`auth.json`) и реализовать проверку роли для режима «Материалы» на сервере.
8. Надёжная запись `hub.json` и `school.json` (fsync, резервные копии, защита от сброса при повреждении).

**Приоритет 3**
9. Убрать прослойку Python: запускать готовый бинарник `graphy-backend`, оставив Python только в образе как интерпретатор для инструментов агента; перенести контрактные тесты на Rust.
10. Тест первого запуска на 3–5 пользователях и правки по результатам.
11. Нагрузочный тест хаба и CI (`cargo test`, `node --test`, `tsc`, e2e школы).
